`agents/claude-code/settings.json` 里原本存着一枚**真实的 OpenRouter 密钥**。

已经替换成 `<YOUR_KEY>`，但因为它曾以明文躺在磁盘上，

这是唯一一件别人无法替你做的事。

## 四、剩下的中危项，为什么不算隐私

### 1. 教材里的反例（3 处）

| 位置 | 内容 | 为什么无害 |
| --- | --- | --- |
| `skills/windows-bat-launcher/SKILL.md` | 一个假用户名拼出来的路径 | 教学用的**虚构路径**，不是任何真实机器上的目录 |
| `skills/workbuddy-spill-enoent/SKILL.md` | 只写了用户目录前缀 + 省略号 | 不指向具体人 |
| `skills/技能库统一规则.md` | 讲「正则转义层级」时的示意写法 | 抽象示意，不对应任何真实目录 |

（本报告自身也会被扫描，所以这里用描述代替具体路径 —— 否则报告就会变成新的命中源。）

### 2. 占位符（本次改造的重点）

改造前，这些文件里写的是**作者本机的真实路径**（某个盘符下的工具目录、技能库目录等）。
问题不只是「泄露」——**它让文档对读者完全无效**：别人机器上没有这个目录，
照着文档找不到东西，只会觉得「这项目是作者自己的，别人用不了」。

现在统一换成 `<工具目录>` / `<技能库>` 这类占位符，并在每处旁边说明
「这个值从哪来」（脚本自动探测后打印，或用户自己指定）。

所以扫描器现在对「本机绝对路径」的规则基本不会命中了。

## 五、商标词条为什么不算侵权

24 处全部来自下面这几类，**都不是「使用了他人作品」，而是「列出不要用的名字」**：

| 位置 | 性质 |
| --- | --- |
| `skills/promo-kit/assets/ip-watchlist.txt` | 禁用名单文件本身 |
| `agents/claude-code/CLAUDE.md` | 规则里写的「注释不要写某某风格」举例 |
| `agents/cursor/rules-skill-library-unified.mdc` | 同上 |

**判断标准很简单**：出现一个作品名，是「用它」还是「禁止用它」？
后者是合规的必要成本 —— 不写出黑名单，用户根本不知道要躲什么。

真要连名字都不出现，得改成「不要写任何已发行游戏的名字」这种泛指，
但那样规则的可读性和约束力都会下降。我们选择保留名单。

另外，仓库里**确实删掉了**两处真实的第三方素材侵权风险：
一个含第三方产品 logo 的示例资源目录（78 文件 / 52.7 MB），
一个含多家厂商产品名的技能（114 文件 / 76.6 MB）。详见 `CREDITS.md`。

## 六、你自己发布前请再扫一遍

```bash
node install/privacy-scan.js
```

如果你往仓库里加了东西，这一步不能省。扫描器会报出：

- 新引入的密钥 / 邮箱 / 手机号
- 你不小心写进去的本机路径
- 第三方作品名

`--fix` 会自动替换一部分（密钥、token、本机路径），但**手机号和作品名不会自动动** ——
那些需要你自己判断是不是该留着。

> **扫描器的一个技术细节**：它用递归遍历（`os.walk` / `fs.readdirSync`）而不是通配符。
> 因为大多数 glob 实现**默认不下钻 `.` 开头的目录**，而隐私恰恰常藏在
> `.git`、`.cursor`、`.claude`、`.workbuddy` 这些地方。
