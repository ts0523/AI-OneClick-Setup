# 工具链清单

> 核心思路：**工具集中装在你自己选的目录里，不装进系统目录、默认不加进 PATH**。
> 卸载 = 删一个文件夹；AI 调工具 = 用绝对路径，不依赖环境变量。

---

## 一、⚠️ 先看这里：路径是你定的，不是本项目定的

**本项目不预设任何盘符。** 你机器上可能是 C 盘、可能是 E 盘、可能装在 D 盘也可能在 NAS 上。

`install/02-install-tools.ps1` 的做法是：

1. **先探测**：从 PATH 和常见安装位置（`C:\Program Files\Git`、`%LOCALAPPDATA%\Programs\...`）找已装的工具，找到就直接用。
2. **找不到才问你要目录**，而且不给死默认值：留空的话脚本会挑一个**空间够的非系统盘**建 `DevTools` 目录；都没有就退回用户目录。
3. 装完**打印可直接复制的绝对路径**，你把它填进 AI 规则文件即可。

想指定位置：

```powershell
powershell -File .\setup.ps1 -ToolRoot "E:\DevTools"
```

## 二、工具清单与推荐布局

装完之后大致长这样（`<<你的工具目录>>` 由你定）：

```
<你的工具目录>\
├── git\                      Git for Windows
│   ├── cmd\git.exe           ← 命令行入口
│   └── mingw64\              Git 自带的 MinGW（可删，但 git 用得到）
├── gh\                       GitHub CLI
│   └── bin\gh.exe            ← 命令行入口
├── mingw64\                  独立 MinGW-w64（编译 C/C++）
│   ├── bin\gcc.exe           C 编译器
│   ├── bin\g++.exe           C++ 编译器
│   └── bin\gdb.exe           调试器
├── ninja\ninja.exe           构建工具（比 make 快很多）
├── node\                     Node.js（跑 JS 脚本 / 装依赖）
│   ├── node.exe
│   └── npm.cmd
├── python\python.exePython（脚本 / 数据处理）
└── 7zip\7z.exe               解压 .7z（装 MinGW 用）
```

> ⚠️ **上表是「装在本工具目录里」的理想布局**，不是唯一正确布局。
> 脚本会先去常见位置（`C:\Program Files\nodejs\`、
> `AppData\Local\Programs\Python\Python313\`、`C:\Program Files\7-Zip\` 等）
> 找已装的工具，找到就直接用 —— **不会**为了「布局整齐」把你已有的工具重装一遍。

### 哪些是必须的

| 工具 | 必需性 | 少了会怎样 |
| --- | --- | --- |
| git | **必须** | 装不了本仓库、推不了 GitHub |
| Node.js | **必须** | AI 工具自身跑不起来，隐私扫描器也跑不了 |
| gh（GitHub CLI） | 强烈建议 | 查不了开源项目、提不了 PR |
| MinGW-w64 + ninja | 编 C/C++ 才需要 | 只写 Python / JS 用不到 |
| Python | 可选 | 很多技能用它做数据处理 |
| 7-Zip | 可选 | 只在装 `.7z` 格式的 MinGW 包时需要 |

### 游戏开发还想装（手动装，脚本不管）

| 目录 | 是什么 | 下载 |
| --- | --- | --- |
| `raylib-5.5_win64_mingw-w64\` | raylib 游戏库（C/C++） | https://www.raylib.com/ |
| `SFML-2.5.1\` / `SFML-3.0.2\` | SFML 游戏库（C++） | https://www.sfml-dev.org/ |
| `blender-5.2.0-windows-x64\` | Blender 建模渲染 | https://www.blender.org/download/ |

## 三、Node.js 与 npm

Node.js 是**整套方案的地基** —— 隐私扫描器是 JS 写的，多数技能的脚本也是 JS。

**优先用 AI 工具自带的托管版本。** 如果你装了 WorkBuddy，它会带一个隔离的 Node：

```
%USERPROFILE%\.workbuddy\binaries\node\versions\<版本号>\node.exe
%USERPROFILE%\.workbuddy\binaries\node\versions\<版本号>\npm.cmd
```

这样做的好处：AI 直接知道路径，**不会和你系统里别的 Node 打架**。
脚本的探测顺序是「PATH → 本工具目录 → 常见安装位置」，
所以装过 AI 工具的话，它大概率会直接找到那个托管版。

想自己装一份便携版：

1. 去 <https://nodejs.org/zh-cn/download> 下 **ZIP 版**（免安装，不动注册表）
2. 解压到你选的工具目录，把那层改名为 `node`
3. 或者把安装包丢进 `installers/`，脚本会自动解压

> 💡 **别用 `npm -g` 全局装包。** 全局包装到系统目录，沙箱环境经常 EPERM 失败。
> 推荐在项目目录下 `npm install`（生成项目内的 `node_modules`）。

## 四、Python

同样，**优先用 AI 工具自带的托管版本**：

```
%USERPROFILE%\.workbuddy\binaries\python\versions\<版本号>\python.exe
```

要自己装的话，Windows 官方安装包记得**勾选「Add Python to PATH」**，
否则脚本探测不到。

> ⚠️ **一个容易踩的坑**：`%LOCALAPPDATA%\Microsoft\WindowsApps\python.exe`
> 是微软商店的**占位转发器** —— 文件一定存在，但真机没装 Python 时
> 双击它会弹商店而不是执行。
> 本项目脚本会实际跑一次拿版本号，**拿不到就当没装**，
> 不会把这个空壳路径写进你的 AI 规则文件。
>
> 这个 bug 是实测抓到的：某台机器上该文件存在，但 `python --version` 什么都不输出，
> 早期版本会把这个空壳当成有效路径打印出来。

### 装依赖别用全局

```powershell
# ❌ 全局装：会掉到系统目录，沙箱里经常 EPERM
& "<你的工具目录>\python\python.exe" -m pip install requests

# ✅ 建虚拟环境，隔离在项目内
& "<你的工具目录>\python\python.exe" -m venv .venv
& ".\.venv\Scripts\python.exe" -m pip install requests
```

## 五、为什么不加进 PATH


**这是本方案最重要的一条设计决定**，理由有三：

1. **AI 在受限环境里常常拿不到完整环境变量。**
   很多 AI 工具（尤其沙箱模式）跑 shell 时继承不到用户的 PATH，
   于是 `git --version` 直接 `command not found`，而它明明装着。
   写死绝对路径就没这个问题。

2. **多版本会互相覆盖。**
   Git 自带一个 MinGW，你可能又装了一个独立 MinGW。
   两个都在 PATH 里时，谁在前面 `gcc` 就是谁 —— 编译行为会飘，
   而且「昨天还好好的今天报错」这种灵异现象大多来自这里。

3. **卸载干净。** 删一个文件夹就完事，不留注册表垃圾。

实在想用短命令：

```powershell
powershell -File .\setup.ps1 -AddToPath
```

⚠️ 脚本会自动排除重复项，但仍要自己确认**只有一个 MinGW 在 PATH 里**。

## 六、怎么验证

```bash
git --version
gh --version
gcc --version
```

或者用绝对路径（推荐，AI 就这么调）：

```powershell
& "<你的工具目录>\git\cmd\git.exe" --version
```

### 编译链自测

```powershell
$gcc = "<你的工具目录>\mingw64\bin\gcc.exe"
Set-Content "$env:TEMP\t.c" 'int main(){return 0;}'
& $gcc "$env:TEMP\t.c" -o "$env:TEMP\t.exe"
& "$env:TEMP\t.exe"; echo "exit=$LASTEXITCODE"    # 期望 0
```

### 用 raylib 编译一个窗口

```powershell
$gcc = "<你的工具目录>\mingw64\bin\gcc.exe"
& $gcc main.c `
  -I"<你的工具目录>\raylib-5.5_win64_mingw-w64\include" `
  -L"<你的工具目录>\raylib-5.5_win64_mingw-w64\lib" `
  -lraylib -o game.exe -static -mwindows `
  -lopengl32 -lgdi32 -lwinmm
```

> `-static -mwindows` 少了会出问题：动态链接会让成品依赖一堆 dll，
> `-mwindows` 才是无黑框窗口。

## 七、离线安装包

`install/02-install-tools.ps1` 会**优先**用 `installers/` 里的离线包。
把下载好的安装包按下面命名放进去：

| 文件名模式 | 对应工具 | 必需性 |
| --- | --- | --- |
| `Git-*-64-bit.exe` | Git for Windows | 必须 |
| `gh_*_windows_amd64.zip` | GitHub CLI | 建议 |
| `node-v*-win-x64*.zip` | Node.js（便携版） | 必须 |
| `python-*-amd64.exe` | Python 官方安装包 | 可选 |
| `x86_64-*.7z` | MinGW-w64 | 编 C/C++ 时 |
| `ninja-win.zip` | ninja | 编 C/C++ 时 |

`installers/` 目录是空的（仓库不塞几十 MB 的二进制）。
想离线安装就自己把官方安装包放进去 —— 命名对上就行，脚本会自动用。

**校验完整性**（无论包从哪来）：

```powershell
Get-FileHash .\Git-2.55.0-64-bit.exe -Algorithm SHA256
```

和官方公布的 SHA256 对一下。

> 网络有 TLS 中间人代理时（公司网、校园网、部分 VPN），
> 下载会报 `unable to verify the first certificate` 或 `CRYPT_E_NO_REVOCATION_CHECK`。
>
> **不要**为了下载成功就关证书校验 —— 那等于放弃对中间人的防护。
> 正确做法：关校验下载 + **用官方 SHA256 校验完整性**，两头都不失守。

## 八、坑

| 坑 | 症状 | 解法 |
| --- | --- | --- |
| **两套 MinGW 打架** | 同一项目昨天能编今天报错，gcc 版本变来变去 | 一律用绝对路径，不要靠 PATH |
| `core.autocrlf` 没关 | 整个文件被标记为已修改，diff 全是假改动 | `git config --global core.autocrlf false` |
| 中文文件名乱码 | `git status` 显示 `\344\270\255` | `git config --global core.quotepath false` |
| 磁盘选错 | 装到 C 盘，C 盘告急 | 装之前先看 `Get-PSDrive` 剩多少 |
| 沙箱里 bash PATH 是坏的 | `ls`/`cp`/`grep` 全 command not found | 用绝对路径调程序；建目录/移动文件用 PowerShell |
| 7z 包解压不了 | 系统没装 7-Zip | 装 7-Zip，或自己用别的工具解 |
